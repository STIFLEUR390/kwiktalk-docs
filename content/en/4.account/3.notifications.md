KwikTalk warns you about events that need action: banned instance, completed
campaign, quota about to be reached, confirmed payment.

Access: **`/notifications`** · Preferences: **`/notifications/preferences`**

## The notification centre

| Action | Route |
|---|---|
| Open the centre | `GET /notifications` |
| Fetch unread ones | `GET /notifications/unread` |
| Mark one as read | `POST /notifications/{notification}/read` |
| Mark all as read | `POST /notifications/read-all` |

The unread counter is exposed continuously: it drives the bell in the UI.

## Event types

| Type | Fired when |
|---|---|
| `instance_disconnected` | A WhatsApp instance disconnects |
| `instance_banned` | A number is banned by WhatsApp |
| `ban_lifted` | A ban is lifted |
| `session_unstable` | The instance session is unstable |
| `new_message` | An incoming message arrives |
| `campaign_paused` | A campaign is paused |
| `campaign_completed` | A campaign completes |
| `import_finished` | A contact import finished |
| `quota_almost_reached` | You are approaching a plan quota |
| `webhook_disabled` | A webhook was disabled |
| `workflow_handoff` | The chatbot hands over to a human |
| `payment_confirmed` | A payment is confirmed |
| `payment_failed` | A payment fails |
| `subscription_expiring` | Your subscription is nearing its end |
| `subscription_expired` | Your subscription expired |

## Channels

Each notification type is routed to **one or more channels**:

| Channel | Meaning |
|---|---|
| `database` | The application's notification centre |
| `mail` | E-mail |
| `whatsapp` | Message on your WhatsApp instance |
| `webpush` | Browser push notification |

## Preferences

The **`/notifications/preferences`** page lists **all types**, each with:

- its **label**,
- the type's **default channels**,
- the **channels actually stored** for your account.

Tick/untick channels, then save.

::u-alert{color="info" icon="i-lucide-info"}
If you untick **all** channels for a type, your preference is **deleted** and the
system falls back to the type default. To never be disturbed by a given type, it
is therefore better to untick channels one by one, or to rely on the defaults.
::

::u-alert{color="warning" icon="i-lucide-triangle-alert"}
**`instance_banned` and `quota_almost_reached` are critical.** Disabling their
channels means risking a banned number or an exhausted plan going unnoticed
before your customers notice.
::

## Browser push

Push requires **subscribing** to your notifications:

| Action | Route |
|---|---|
| Fetch the public VAPID key | `GET /push/vapid-key` |
| Subscribe | `POST /push/subscribe` |
| Unsubscribe | `POST /push/unsubscribe` |

The public key is fetched and used to register the browser **Push API**
subscription. You can unsubscribe at any time.
