Two levels of sending:

- **[Send a message](#send-a-message)** — one or a few recipients, by hand.
- **[Campaigns](#campaigns)** — many recipients, with batching, delays and
  scheduling.

Access: **`/admin/messages`** and **`/admin/message-campaigns`**

## Send a message

1. Go to **Messages → Send**.
2. Pick the sending **instance**.
3. Enter the **recipients** (numbers or contacts).
4. Write the content or choose a **template**.
5. Send.

The message is created with status `sending`, then follows its lifecycle.

### Message statuses

| Status | Meaning |
|---|---|
| `pending` | Queued |
| `sending` | Being sent |
| `sent` | Handed to WhatsApp's servers |
| `delivered` | Delivered to the recipient's device |
| `read` | Read |
| `failed` | Failed |

::u-alert{color="info" icon="i-lucide-eye"}
The `sent → delivered → read` transitions arrive in **real time** (Reverb). To
follow them outside the UI, wire up a
[webhook `message.status.updated`](/en/integrations/webhooks).
::

## Campaigns

A campaign sends one **template** to a **selection of contacts**.

### Create a campaign

1. **Campaigns → Create**.
2. Name and describe it.
3. Choose the **message template** to send.
4. Define the **target**:
   - one or more **contact groups**, or
   - an **Excel file** imported straight into the campaign.
5. Configure the send (below).
6. Save.

### Configure the send

| Setting | Role |
|---|---|
| **Batch size** (`batch_size`) | Messages sent in a row |
| **Batch delay** (`batch_delay_seconds`) | Pause, in seconds, between batches |
| **Max retries** (`max_retries`) | Automatic retries per message on failure |
| **Schedule** (`scheduled_for`) | Start date and time |
| **Timezone** | Per-campaign timezone: the scheduled time is interpreted in **that** zone |

::u-alert{color="warning" icon="i-lucide-timer"}
The **batch delay** is your first ally against banning. A delay that is too short
on a large list is the #1 cause of a suspended number. See
[Anti-spam protection](/en/resources/anti-spam).
::

### Lifecycle

A campaign goes through these statuses:

```
draft ─→ scheduled ─→ running ─→ completed
              │           │
              └─────→ paused ──→ running
                                    │
                                 failed
```

| Action | Effect |
|---|---|
| **Start** | Moves the campaign to `running` |
| **Pause** | Stops cleanly, state is kept |
| **Resume** | Picks up where it stopped |
| **Delete** | Destroys the campaign |

Automatic start of `scheduled` campaigns is handled by the Laravel scheduler at
the `scheduled_for` time.

### Tracking

A campaign exposes live counters:

- `messages_sent`
- `messages_delivered`
- `messages_failed`
- `messages_pending`

The campaign detail page lists each **recipient** individually
(`message_campaign_recipients`), with its own status and the **skipped** contacts
(`skipped_contacts`).

::u-alert{color="info" icon="i-lucide-pause-circle"}
If **anti-ban protection** triggers an automatic pause, the campaign moves to
`paused` and the reason is recorded (`anti_ban_pause_reason`,
`anti_ban_paused_at`). It resumes by itself once the number is usable again.
::

### Quotas

| Plan | Concurrent campaigns |
|---|:---:|
| Starter | 2 |
| Growth | 20 |
| Business | ∞ |

## Edge cases

- **Skipped contacts** — an already-processed or invalid contact may be excluded
  from the campaign; it appears under `skipped_contacts`.
- **Permanent failure** — messages that failed for good end up in the
  **instance DLQ**, replayable one by one (see
  [WhatsApp instances](/en/features/whatsapp-instances)).
