Every message **received** on your instances is collected here: campaign replies,
questions, free-text acknowledgements…

Access: **`/admin/incoming-messages`**

::u-alert{color="info" icon="i-lucide-inbox"}
The `user` role holds the `view incoming messages` and
`manage incoming messages` permissions: conversation tracking is part of the
standard workspace, with no need to go through administration.
::

## What gets captured

Each incoming message keeps:

| Field | Content |
|---|---|
| `content` | Message body |
| `message_type` | Type: text, image, document, audio… |
| `from_me` | Whether the message came from your own number |
| `media_url` | Received attachment (with `media_filename`, `media_mimetype`, `media_caption`) |
| `chat_jid` | WhatsApp conversation identifier |
| `contact_id` | Linked contact, if identified |
| `evolution_message_id` | Identifier on the Evolution API side |
| `delivered` / `delivered_at` | Whether KwikTalk ingested it |
| `failed` / `error_message` | If processing failed |

## List and inspect

The list can be filtered; the detail page shows a message and its context.

- **`/admin/incoming-messages`** — the list.
- **`/admin/incoming-messages/{id}`** — the detail.

## Link to a contact

When the sender matches a number in your base, the message is linked to that
**contact** (`contact_id`) and appears in their history. Otherwise you can create
the contact from the number.

::u-alert{color="warning" icon="i-lucide-message-circle-warning"}
This is exactly why you **validate numbers** before a campaign: the more
up-to-date your base is, the more incoming replies are attached to the right
person automatically. See
[Contacts and groups](/en/features/contacts-groups).
::

## Reply

From the detail page you can reply to the contact on the relevant instance. The
reply follows the same status cycle as an outgoing message.

## Automate replies

Incoming messages are the **trigger** for the [chatbot](/en/features/chatbot)
and are exposed to integrations through the `message.received` webhook.

To fetch incoming messages **from an external application**, use
`GET /api/v1/messages` — see
[API applications](/en/integrations/api-applications).
