The chatbot automatically replies to
[incoming messages](/en/features/incoming-messages) in three modes.

Access: **`/admin/chatbots`**

::u-alert{color="warning" icon="i-lucide-lock"}
The chatbot is available on the **Growth** and **Business** plans
(`chatbot_access`). The **Starter** plan has no chatbot at all.
::

## The three modes

| Mode | Principle | When to use it |
|---|---|---|
| **`rules`** | An ordered list: trigger → reply | Simple, deterministic replies |
| **`workflow`** | A graph of nodes with branches | Multi-step flows, conditions |
| **`webhook`** | The message goes to **your** endpoint, your service replies | Business logic, AI, CRM |

### `rules` mode

Each rule pairs a **trigger** with a **reply**.

Available **trigger types**:

| Type | Matches |
|---|---|
| `contains` | The message contains the string |
| `starts_with` | The message starts with |
| `ends_with` | The message ends with |
| `exact` | The message is exactly |
| `regex` | A regular expression |

**Replies**: either plain **text** (`text`) or a
**[message template](/en/features/message-templates)** (`template`).

Rules are ordered by **priority** (`priority`) and can be enabled or disabled
individually (`is_active`).

### `workflow` mode

A workflow is a graph of nodes. Each plan sets a **maximum number of nodes**:

| Plan | Workflow nodes |
|---|:---:|
| Growth | 15 |
| Business | ∞ |

The workflow is editable and has a **simulation**: test a path before enabling it
in production.

### `webhook` mode

The chatbot posts the message to an URL you control. Testable straight from the
UI (`test-webhook`) before enabling.

Choose this mode to plug in an AI model, n8n or your backend.

## Guard rails

The chatbot is not an open loop: several limits constrain it.

| Setting | Role |
|---|---|
| **`max_replies_per_day`** | Maximum replies per day |
| **`cooldown_minutes`** | Minimum delay between two replies to the same contact |
| **`fallback_message`** | Message sent when no rule matches |
| **`human_override_window_min`** | Window during which **a human** takes over and the bot stays quiet |
| **`daily_replies_count` / `daily_replies_date`** | Daily counter, reset every day |
| **`paused_at`** | Pause timestamp |

::u-alert{color="info" icon="i-lucide-user-check"}
The **human handoff window** (`human_override_window_min`) matters: if an agent
starts typing, the bot stays silent for that delay. It prevents double replies
and contradictions.
::

## Scope the bot

The chatbot can deliberately limit itself:

- **Contacts only** (`contacts_only`) — ignore numbers unknown to your base.
- **Excluded groups** (`exclude_groups`) — stay out of certain contact groups
  (VIP customers, complaints…).

## Enable, test, suspend

| Action | Effect |
|---|---|
| **Test** | Sends a simulated message and shows the reply (`test`) |
| **Test webhook** | Checks that your endpoint responds (`test-webhook`) |
| **Enable / disable** | Toggle the chatbot without deleting it (`toggle`) |
| **Pause** | Immediate suspension (`pause`) |
| **Resume** | Continue where it stopped (`resume`) |

## Quotas

| Plan | Chatbots | Rules |
|---|:---:|:---:|
| Starter | 0 | 0 |
| Growth | 1 | 20 |
| Business | ∞ | ∞ |
