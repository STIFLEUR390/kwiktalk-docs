An **API application** carries a **key** that authenticates your calls. Each key
is **bound to a single WhatsApp instance**, so calls always go through the right
number without specifying it in the request.

Access: **`/admin/api-applications`**

::u-alert{color="warning" icon="i-lucide-lock"}
The **Starter** plan allows **no API application**
(`max_api_applications = 0`). You need at least **Growth** (3 keys), unlimited on
**Business**. See [Pricing](/en/overview/pricing).
::

## Create an application

1. **API applications → Create**.
2. Name it and bind it to an **instance**.
3. The key is generated once — **copy it immediately**.

The key is stored **hashed** (`sha256`): KwikTalk cannot show it to you again. If
you lose it, you must **regenerate** one (`regenerate`), which invalidates the
previous key.

Each application exposes:

- its active/inactive state (`isActive()`) — an inactive key is refused with `403`;
- its own **rate limit**;
- its last use (`last_used_at`).

## Authenticate your calls

Required header:

```http
Authorization: Bearer <your_key>
```

No key → `401 missing_api_key`. Unknown key → `401 invalid_api_key`.
Inactive or expired key → `403 inactive_api_key`.

::u-alert{color="warning" icon="i-lucide-unplug"}
If the **bound instance is not connected**, every call fails with
`403 instance_disconnected`. This is the #1 API error cause: check the instance
state first. See [WhatsApp instances](/en/features/whatsapp-instances).
::

## Rate limit

Each key has its own limit, expressed in requests per minute
(300/min by default, adjustable per application).

Responses include:

```http
X-RateLimit-Limit: 300
X-RateLimit-Remaining: 287
```

Above the limit → `429 rate_limit_exceeded`.

## Endpoints

Base: **`/api/v1`**

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/v1/messages/send` | Send a message |
| `GET` | `/api/v1/messages` | List messages |
| `POST` | `/api/v1/contacts/verify` | Check whether a number is on WhatsApp |
| `GET` | `/api/v1/webhooks` | List your webhooks |
| `POST` | `/api/v1/webhooks` | Create a webhook |
| `GET` | `/api/v1/webhooks/{id}` | Webhook detail |
| `PATCH` | `/api/v1/webhooks/{id}` | Update a webhook |
| `DELETE` | `/api/v1/webhooks/{id}` | Delete a webhook |

### Send a message

```bash
curl -X POST https://api.kwiktalk.app/api/v1/messages/send \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"to": "+2250700000000", "message": "Hello {name}!"}'
```

![KwikTalk API response](/images/api-response.png)

Parameters:

| Field | Required | Constraint |
|:---:|:---:|---|
| `to` | ✅ | text, **max 20 characters** (international format) |
| `message` | ✅ | text, **max 4096 characters** |

Response: `{ "success": true, "data": { "message_id": 4821 } }`.

On send failure: `422 send_failed` with the reason, and the message is marked
`failed` on the KwikTalk side.

::u-alert{color="info" icon="i-lucide-braces"}
You can use the `{name}` and `{phone}` template variables in `message` — they are
rendered with the recipient's data. See
[Message templates](/en/features/message-templates).
::

### Verify a number

```bash
curl -X POST https://api.kwiktalk.app/api/v1/contacts/verify \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"phone_number": "+2250700000000"}'
```

Tells you whether the number really exists on WhatsApp — useful **before** a
campaign.

### List messages

`GET /api/v1/messages` returns the instance message history with a `limit`
(50 by default). Use it to fetch send status without polling the UI.

## Best practices

- **Do not regenerate the key without reason**: every production integration
  must be updated at the same time.
- **One key = one job**: separate, say, the CRM and the website into two
  applications to isolate quotas and debugging.
- **Watch `X-RateLimit-Remaining`** before sending a spike.
- **Test first** with a message to your own number.
