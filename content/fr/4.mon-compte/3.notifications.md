KwikTalk vous prévient des événements qui demandent une action : instance
bannie, campagne terminée, quota bientôt atteint, paiement confirmé.

Accès : **`/notifications`** · Préférences : **`/notifications/preferences`**

## Le centre de notifications

| Action | Route |
|---|---|
| Ouvrir le centre | `GET /notifications` |
| Récupérer les non lues | `GET /notifications/unread` |
| Marquer une notification comme lue | `POST /notifications/{notification}/read` |
| Tout marquer comme lu | `POST /notifications/read-all` |

Le compteur de non lues est exposé en continu : c'est lui qui pilote la cloche de
l'interface.

## Les types d'événements

| Type | Déclenché quand |
|---|---|
| `instance_disconnected` | Une instance WhatsApp se déconnecte |
| `instance_banned` | Un numéro est banni par WhatsApp |
| `ban_lifted` | Un bannissement est levé |
| `session_unstable` | La session de l'instance est instable |
| `new_message` | Un message entrant arrive |
| `campaign_paused` | Une campagne est mise en pause |
| `campaign_completed` | Une campagne est terminée |
| `import_finished` | Un import de contacts est terminé |
| `quota_almost_reached` | Vous approchez d'un quota de plan |
| `webhook_disabled` | Un webhook a été désactivé |
| `workflow_handoff` | Le chatbot passe la main à un humain |
| `payment_confirmed` | Un paiement est confirmé |
| `payment_failed` | Un paiement échoue |
| `subscription_expiring` | Votre abonnement arrive à échéance |
| `subscription_expired` | Votre abonnement a expiré |

## Les canaux

Chaque type de notification est routé vers **un ou plusieurs canaux** :

| Canal | Signification |
|---|---|
| `database` | Centre de notifications de l'application |
| `mail` | E-mail |
| `whatsapp` | Message sur votre instance WhatsApp |
| `webpush` | Notification navigateur (push) |

## Préférences

La page **`/notifications/preferences`** liste **tous les types**, avec pour
chacun :

- son **libellé**,
- les **canaux par défaut** du type,
- les **canaux effectivement retenus** pour votre compte.

Vous cochez/décochez les canaux, puis enregistrez.

::u-alert{type="info" icon="i-lucide-info"}
Si vous décochez **tous** les canaux d'un type, votre préférence est **supprimée**
et le système retombe sur le défaut du type. Pour ne plus jamais être dérangé par
un type précis, il faut donc plutôt désactiver chaque canal un par un, ou bien
vous fier aux défauts.
::

::u-alert{color="warning" icon="i-lucide-triangle-alert"}
**`instance_banned` et `quota_almost_reached` sont critiques.** Désactiver leurs
canaux, c'est risquer de ne pas voir un numéro banni ou un plan épuisé avant vos
clients.
::

## Notifications navigateur (push)

Le push nécessite une **abonnement** à vos notifications :

| Action | Route |
|---|---|
| Récupérer la clé publique VAPID | `GET /push/vapid-key` |
| S'abonner | `POST /push/subscribe` |
| Se désabonner | `POST /push/unsubscribe` |

La clé publique est récupérée puis utilisée pour enregistrer une **subscription**
Push API du navigateur. Vous pouvez vous désabonner à tout moment.
