Une **application API** porte une **clé** qui authentifie vos appels. Chaque clé est
**rattachée à une seule instance WhatsApp** : les appels passent donc toujours par
le bon numéro, sans le préciser dans la requête.

Accès : **`/admin/api-applications`**

::u-alert{color="warning" icon="i-lucide-lock"}
Le plan **Starter** n'autorise **aucune application API**
(`max_api_applications = 0`). Il faut au minimum **Growth** (3 clés), illimité sur
**Business**. Voir [Tarifs](/fr/overview/pricing).
::

## Créer une application

1. **Applications API → Créer**.
2. Nommez-la et rattachez-la à une **instance**.
3. La clé est générée une seule fois — **copiez-la immédiatement**.

La clé est stockée **hachée** (`sha256`) : KwikTalk ne peut pas la vous
remontrer. Si vous la perdez, il faut en **régénérer** une
(`regenerate`), ce qui invalide l'ancienne.

Chaque application expose :

- son état actif/inactif (`isActive()`) — une clé inactive est refusée en `403` ;
- sa **limite de débit** propre (`rate_limit`) ;
- sa dernière utilisation (`last_used_at`).

## Authentifier ses appels

En-tête obligatoire :

```http
Authorization: Bearer <votre_cle>
```

Sans clé → `401 missing_api_key`. Clé inconnue → `401 invalid_api_key`.
Clé inactive ou expirée → `403 inactive_api_key`.

::u-alert{color="warning" icon="i-lucide-unplug"}
Si l'**instance liée n'est pas connectée**, tous les appels échouent en
`403 instance_disconnected`. C'est la cause n°1 d'erreur API : vérifiez d'abord
l'état de l'instance. Voir
[Instances WhatsApp](/fr/features/whatsapp-instances).
::

## Limite de débit

Chaque clé a sa propre limite, exprimée en requêtes par minute
(300/min par défaut, personnalisable par application).

Les réponses incluent les en-têtes :

```http
X-RateLimit-Limit: 300
X-RateLimit-Remaining: 287
```

Au-delà → `429 rate_limit_exceeded`.

## Endpoints

Base : **`/api/v1`**

| Méthode | Chemin | Rôle |
|---|---|---|
| `POST` | `/api/v1/messages/send` | Envoyer un message |
| `GET` | `/api/v1/messages` | Lister les messages |
| `POST` | `/api/v1/contacts/verify` | Vérifier qu'un numéro est sur WhatsApp |
| `GET` | `/api/v1/webhooks` | Lister vos webhooks |
| `POST` | `/api/v1/webhooks` | Créer un webhook |
| `GET` | `/api/v1/webhooks/{id}` | Détail d'un webhook |
| `PATCH` | `/api/v1/webhooks/{id}` | Modifier un webhook |
| `DELETE` | `/api/v1/webhooks/{id}` | Supprimer un webhook |

### Envoyer un message

```bash
curl -X POST https://api.kwiktalk.app/api/v1/messages/send \
  -H "Authorization: Bearer VOTRE_CLE_API" \
  -H "Content-Type: application/json" \
  -d '{"to": "+2250700000000", "message": "Bonjour {name} !"}'
```

![Réponse de l'API KwikTalk](/images/api-response.png)

Paramètres :

| Champ | Requis | Contrainte |
|---|:---:|---|
| `to` | ✅ | texte, **20 caractères max** (format international) |
| `message` | ✅ | texte, **4096 caractères max** |

Réponse : `{ "success": true, "data": { "message_id": 4821 } }`.

En cas d'échec d'envoi : `422 send_failed` avec le motif, et le message est marqué
`failed` côté KwikTalk.

::u-alert{type="info" icon="i-lucide-braces"}
Vous pouvez utiliser les variables de modèle `{name}` et `{phone}` dans `message`
— elles sont rendues avec les données du destinataire. Voir
[Modèles de messages](/fr/features/message-templates).
::

### Vérifier un numéro

```bash
curl -X POST https://api.kwiktalk.app/api/v1/contacts/verify \
  -H "Authorization: Bearer VOTRE_CLE_API" \
  -H "Content-Type: application/json" \
  -d '{"phone_number": "+2250700000000"}'
```

Indique si le numéro existe réellement sur WhatsApp — utile **avant** une campagne.

### Lister les messages

`GET /api/v1/messages` renvoie l'historique des messages de l'instance, avec un
`limit` (50 par défaut). Permet de récupérer l'état des envois sans pollinger
l'interface.

## Bonnes pratiques

- **Ne regénérez pas la clé sans nécessité** : toute intégration en production
  doit être mise à jour en même temps.
- **Une clé = un usage** : séparez, par exemple, le CRM et le site web en deux
  applications distinctes pour isoler quotas et diagnostics.
- **Surveillez `X-RateLimit-Remaining`** avant d'envoyer un pic.
- **Testez d'abord** avec un message vers votre propre numéro.
