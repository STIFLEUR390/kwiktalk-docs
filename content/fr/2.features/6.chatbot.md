Le chatbot répond automatiquement aux [messages entrants](/fr/features/incoming-messages)
selon trois modes.

Accès : **`/admin/chatbots`**

::u-alert{color="warning" icon="i-lucide-lock"}
Le chatbot est réservé aux plans **Growth** et **Business** (`chatbot_access`).
Le plan **Starter** ne dispose d'aucun chatbot.
::

## Les trois modes

| Mode | Principe | Quand l'utiliser |
|---|---|---|
| **`rules`** | Une liste de règles : déclencheur → réponse | Réponses simples et déterministes |
| **`workflow`** | Un graphe de nœuds avec branches | Parcours multi-étapes, conditions |
| **`webhook`** | Le message part vers **votre** endpoint, c'est votre service qui répond | Logique métier, IA, CRM |

### Mode `rules`

Chaque règle associe un **déclencheur** à une **réponse**.

**Types de déclencheurs** disponibles :

| Type | Correspond à |
|---|---|
| `contains` | Le message contient la chaîne |
| `starts_with` | Le message commence par |
| `ends_with` | Le message finit par |
| `exact` | Le message est exactement |
| `regex` | Une expression régulière |

**Réponses** : soit un **texte** direct (`text`), soit un
**[modèle de message](/fr/features/message-templates)** (`template`).

Les règles sont ordonnées par **priorité** (`priority`) et peuvent être activées
ou désactivées individuellement (`is_active`).

### Mode `workflow`

Un workflow est un graphe de nœuds. Chaque plan fixe un **nombre maximal de
nœuds** :

| Plan | Nœuds de workflow |
|---|:---:|
| Growth | 15 |
| Business | ∞ |

Le workflow est éditable, et dispose d'une **simulation** : testez un parcours
avant de l'activer en production.

### Mode `webhook`

Le chatbot transmet le message à une URL que vous contrôlez. Testable directement
depuis l'interface (`test-webhook`) avant d'activer.

C'est le mode à choisir pour brancher un modèle IA, n8n ou votre backend.

## Garde-fous

Le chatbot n'est pas une boucle ouverte : plusieurs limites encadrent son
comportement.

| Réglage | Rôle |
|---|---|
| **`max_replies_per_day`** | Nombre maximal de réponses par jour |
| **`cooldown_minutes`** | Délai minimum entre deux réponses au même contact |
| **`fallback_message`** | Message envoyé quand aucune règle ne correspond |
| **`human_override_window_min`** | Fenêtre pendant laquelle **un humain** reprend la main sans que le bot réponde |
| **`daily_replies_count` / `daily_replies_date`** | Compteur quotidien, remis à zéro chaque jour |
| **`paused_at`** | Horodatage de la mise en pause |

::u-alert{type="info" icon="i-lucide-user-check"}
La **fenêtre de reprise humaine** (`human_override_window_min`) est importante :
si un conseiller commence à écrire, le bot se tait pendant ce délai. Évite les
réponses en double et les contradictions.
::

## Restreindre le périmètre

Le chatbot peut se limiter volontairement :

- **Contacts seulement** (`contacts_only`) — ignore les numéros inconnus de la base.
- **Groupes exclus** (`exclude_groups`) — n'intervient pas sur les contacts de
  certains groupes (clients VIP, réclamations…).

## Activer, tester, suspendre

| Action | Effet |
|---|---|
| **Tester** | Envoie un message simulé et affiche la réponse (`test`) |
| **Tester le webhook** | Vérifie que votre endpoint répond (`test-webhook`) |
| **Activer / désactiver** | Basculer le chatbot sans le supprimer (`toggle`) |
| **Mettre en pause** | Suspension immédiate (`pause`) |
| **Reprendre** | Reprendre là où il s'était arrêté (`resume`) |
