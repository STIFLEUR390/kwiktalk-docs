L'API KwikTalk permet à **votre application** d'envoyer des messages WhatsApp
depuis votre numéro, et de suivre ce qui a été envoyé.

Accès : menu de gauche → **Applications API**

::u-alert{color="info" icon="i-lucide-lock"}
L'API est incluse à partir du plan **Growth** (3 applications) et illimitée sur
Business. Sur Starter, l'entrée de menu n'apparaît pas — voir
[Plans et quotas](/fr/billing/plans).
::

## Créer une clé API

1. Connectez d'abord l'**instance WhatsApp** qui enverra les messages.
2. **Applications API → Créer une application**.
3. Donnez-lui un **nom** (« Site e-commerce », « CRM ») et choisissez
   l'**instance WhatsApp** associée.
4. **Copiez la clé affichée immédiatement** : elle n'est plus jamais réaffichée.
   Seul son préfixe reste visible dans la liste.

::u-alert{color="warning" icon="i-lucide-key-round"}
Une clé donne le pouvoir d'envoyer des messages depuis votre numéro. Gardez-la
côté serveur, jamais dans du code client ou un dépôt public. Si elle fuite,
**Régénérer la clé** invalide l'ancienne instantanément.
::

Chaque clé est liée à **une instance**. Pour envoyer depuis deux numéros, créez
deux applications.

## Authentification

Toutes les requêtes portent la clé dans un en-tête `Authorization` :

```
Authorization: Bearer VOTRE_CLE_API
```

Base des URLs : `https://<votre-instance-kwiktalk>/api/v1`

## Envoyer un message

`POST /api/v1/messages/send`

```bash
curl -X POST https://kwiktalk.exemple.com/api/v1/messages/send \
  -H "Authorization: Bearer VOTRE_CLE_API" \
  -H "Content-Type: application/json" \
  -d '{"to":"2250701020304","message":"Bonjour, votre commande est prête."}'
```

| Champ | Type | Règle |
|---|---|---|
| `to` | texte | Numéro au format international, sans `+`. 20 caractères max. |
| `message` | texte | 4 096 caractères max. |

Réponse :

```json
{ "success": true, "data": { "message_id": 1234 } }
```

## Historique des messages

`GET /api/v1/messages`

```bash
curl "https://kwiktalk.exemple.com/api/v1/messages?status=delivered&limit=50" \
  -H "Authorization: Bearer VOTRE_CLE_API"
```

| Paramètre | Valeurs |
|---|---|
| `status` | `pending`, `sending`, `sent`, `delivered`, `read`, `failed` |
| `limit` | 1 à 100 (50 par défaut) |
| `before` | identifiant d'un message : renvoie ceux qui le précèdent |

La réponse contient pour chaque message l'identifiant, le destinataire, le type,
le contenu, le statut, l'identifiant de campagne et les dates d'envoi.

## Vérifier qu'un numéro existe sur WhatsApp

`POST /api/v1/contacts/verify`

```bash
curl -X POST https://kwiktalk.exemple.com/api/v1/contacts/verify \
  -H "Authorization: Bearer VOTRE_CLE_API" \
  -H "Content-Type: application/json" \
  -d '{"phone_number":"2250701020304"}'
```

```json
{ "success": true, "data": { "is_whatsapp_user": true, "jid": "2250701020304@s.whatsapp.net" } }
```

Cette vérification est gratuite en temps réel mais coûte une requête à WhatsApp :
ne l'appelez pas en boucle sur la même liste.

## Limite de débit

Chaque clé a sa propre limite, **300 requêtes par minute** par défaut. Au-delà,
l'API répond `429`. Envoyez vos messages en séquence plutôt qu'en parallèle, et
respectez un délai entre deux envois (3 à 10 secondes) : c'est ce qui protège
votre numéro.

## Erreurs

Toutes les erreurs renvoient un JSON de la forme :

```json
{ "success": false, "code": "invalid_api_key", "message": "Invalid API key." }
```

| Code HTTP | `code` | Cause |
|---|---|---|
| 401 | `missing_api_key` | En-tête `Authorization: Bearer …` absent |
| 401 | `invalid_api_key` | Clé inconnue ou révoquée |
| 403 | `inactive_api_key` | Application désactivée |
| 403 | `instance_disconnected` | L'instance liée n'est plus connectée |
| 422 | `send_failed` | WhatsApp a refusé l'envoi (`message` contient le motif) |
| 422 | `verification_failed` | La vérification du numéro a échoué |
| 429 | — | Limite de débit atteinte |

## Ce que l'API ne fait pas

La gestion des contacts, des groupes, des modèles, des campagnes et du chatbot
reste dans l'interface. L'API couvre l'envoi, l'historique et la vérification d'un
numéro.

## Bonnes pratiques

- **Une clé par intégration** : vous pouvez révoquer l'une sans casser les autres.
- **Journalisez les `message_id`** : c'est ce qui permet de rapprocher un envoi
  d'un statut dans l'historique.
- **Gérez les `429`** avec une temporisation, pas avec des reprises immédiates.
- **Vérifiez le numéro** avant un envoi important : un numéro invalide est un
  échec qui pèse sur la réputation de votre instance.
